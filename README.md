# 작은 스시집 V9 — 콤보 시식·기행 기믹·시점 자유·연속 썰기 수정

V8의 8인 멀티플레이, 사용자 지정 방 코드, 실시간 칼질 관람, 손님별 접시와 회 두께, 채팅 말풍선, 셰프의 몰래 먹기, 맛 칭찬/혹평, 오프라인 1인 모드를 유지합니다.

## V9에서 새로 고친 것

### 1) 연속 썰기 멈춤 수정
- **원인**: 화면의 칼질 애니메이션이 끝나자마자 다음 `slice`를 보내면 서버가 이전 칼질을 아직 처리 중이라 거절하고, 자동 연속 썰기도 그대로 멈추던 타이밍 문제가 있었습니다.
- **변경**: 서버에서 마지막 컷이 확정되고 `cutting:null`인 새 상태를 통지할 때까지 대기한 다음, 로컬 애니메이션도 끝났으면 다음 컷을 보냅니다. 서버 완료가 먼저 와도 로컬 애니메이션을 기다립니다.
- 같은 서버에서 연속 컷 10개, 완료 이벤트 10회, 완성 회 분배, 새 참치 준비 뒤 손님 접시 보존을 자동 테스트했습니다.
- 참치를 끝까지 썰면 자동 썰기가 끝나며 **새 참치 준비** 후 다시 **연속 썰기**를 누르면 됩니다.

### 2) 혼자 먹을 때의 대사: 랜덤 중복 방지 + 콤보
- **32개 반응 상황, 총 155개의 새로운 독립 대사**: 그냥 먹기 / 간장 / 와사비 / 두 조합 / 두께가 얇거나 두꺼운 회 / 연속 시식 / 사케 후 참치 / 참치 후 사케 / 간장만 찍은 젓가락 후 참치 / 통째 간장 후 참치 / 와사비 직후 참치 / 종지 들어 마시기 / 도쿠리 직접 마시기 등.
- **섞인 카드 묶음(shuffle bag)**: 같은 상황의 대사를 전부 한 번씩 사용할 때까지는 그 대사가 다시 나오지 않습니다. 모든 대사를 소진하면 재셔플하고 직전 대사와 겹치지 않게 조정합니다.
- **접시 교체 인식**: 새로 식사를 시작하거나 빈 접시가 새로 채워질 때는 첫 대사를 달리 고릅니다. 이전 접시의 첫 대사와 같은 대사가 바로 다시 뜨지 않습니다.
- **상황별 우선순위**: 각 행동 직전에 했던 조작을 최근 12~26초 이력으로 기록해 대사를 전환합니다. 마지막 회를 먹으면 후속 완식 문구가 별도로 출력됩니다.
- 체감상 똑같은 시식 문장만 연속해서 나오는 문제를 줄였고, 맛의 첫인상·지방·식감·감칠맛·뒷맛을 분리해 묘사합니다.

### 3) 새로 조작 가능한 물건

**식사 화면에서 마우스/터치로 잡은 뒤 아래쪽 '입' 영역으로 가져가서 놓으세요.**

| 대상 | 동작 | 반응 |
|---|---|---|
| 사케잔 | 잔을 들어 입으로 가져가기 | 빈 잔인지 실제 술이 있는지에 따라 다른 대사. 연속 음주 2회, 3회, 4회 이상 반응 |
| 사케병(도쿠리) | 잔 없이 병째 입으로 가져가기 | 병을 들어 기울여 마시는 모션, 병째 마시기 전용 대사와 재시도 반응 |
| 간장 종지 | **그릇 테두리**를 젓가락 없이 잡아 드래그 | 종지 들어 마시는 모션. 빈 그릇 / 간장 / 와사비 섞인 간장 구분, 간장 양 초기화 |
| 간장통 | 통째 입으로 드래그 | 원액을 먹으려는 장난에 맞는 과장 효과와 시식평 |
| 와사비통 | 통째 입으로 드래그 | 알싸한 충격, 코끝·눈물 등의 요리만화풍 연출 |
| 젓가락 | 간장만 찍은 후 회 없이 입으로 이동 | '간장만 시식' 전용 반응. 아무것도 묻지 않으면 다른 반응 |
| 참치 조각 | 간장/와사비 찍은 뒤 또는 아무것도 안 찍고 입으로 | 당시 두께/양념/최근 조작에 따라 대사 변경 |

병/종지를 직접 마시는 장난은 **게임 속 과장 연출**입니다. 실제 원액 간장·와사비를 마시는 행동을 권장하는 것이 아닙니다. 사케 연속 섭취 기믹에서도 반복 시 물을 마시고 쉬는 내용의 코믹한 반응이 나옵니다.

### 4) 식사 카메라 시점 복구·선택
- 식사 화면에 진입할 때 **원본 HTML과 같은 기본 각도**(`카메라 0,6.2,8.4 / 응시 .2,1,.2`)로 되돌립니다.
- 화면 좌측 상단에 작은 `기본 각도` / `접시 가까이` / `측면` / `위에서` 카메라 메뉴가 나타납니다.
- **빈 공간을 드래그**하면 자유 회전, **마우스 휠**은 확대/축소, **우클릭 드래그**는 시점 이동입니다.
- 소품을 집었을 때는 자유 회전을 잠시 끄고 놓으면 다시 켜서 기존 아이템 드래그와 충돌하지 않게 했습니다.

## 실행

### Render에 배포한 멀티플레이
이 폴더의 `index.html`, `multiplayer.js`, `server.js`, `package.json`, `README.md`를 기존 GitHub `sushi-bar` 저장소 최상위에 **파일 내용 그대로 덮어쓰기**하고 Commit합니다. Render의 기존 `npm install` / `npm start` 설정을 유지하면 됩니다. 새 Render 서버는 필요 없습니다.

배포가 완료되면 접속 중인 사람 전부 브라우저를 **Ctrl+Shift+R (강력 새로고침)** 하여 서로 같은 버전으로 접속하세요.

### PC 오프라인 완전 실행
1. 압축을 풀고, 인터넷이 연결된 상태에서 한 번 `setup-offline.bat` 실행 (Windows).
2. 엔진 다운로드 완료 후 `offline.html` 더블클릭. 그 뒤에는 인터넷과 Node.js 서버가 필요하지 않습니다.
3. `offline.html`, `multiplayer.js`, `vendor/three.min.js`, `vendor/OrbitControls.js`를 함께 보관해야 합니다.

ZIP에는 `three.min.js`, `OrbitControls.js` 자체가 포함되지 않았습니다. 로컬 제작 환경에서 외부 파일을 다운로드할 수 없어, 최초 1회 `setup-offline.bat`으로 받는 방식은 기존 V8과 동일합니다.

## 검증 상태
- `node --check`로 웹/오프라인 인라인 JS, `multiplayer.js`, `server.js` 문법 검사 통과.
- 대사 테스트: 전체 32개 상황, 문구 155개, 동일 카테고리 비반복 셔플, 새로운 접시의 첫 대사 연속 중복 방지, 조작별 반응 이벤트 확인.
- 가상 소켓 서버 테스트: 방 참가, 10회 연속 절단 및 완료 상태, 손님 개인 접시, 참치 재준비 후 기존 회 보존 확인.
- **실제 브라우저의 Three.js 3D 렌더링과 실제 Render 8인 동시 접속 검증은 이 환경의 외부 엔진 다운로드 제한으로 수행하지 못했습니다.** 따라서 소품의 3D 클릭 판정과 카메라 시각 배치는 배포 후 직접 확인이 필요합니다.
