# 작은 스시집 V5 — 실시간 조리 관람 + 손님별 개인 테이블

기존 실사 스타일 3D 참치 썰기·간장·와사비·사케, 8인 방 코드/채팅/셰프 교대를 유지하면서 **칼질 애니메이션을 같은 방의 접속자에게 동기화**하고, **회는 접속자별 독립된 접시에서 먹도록 변경**한 버전입니다.

## 배포

1. GitHub의 **기존 `sushi-bar` 저장소**에서 `index.html`, `server.js`, `multiplayer.js`, `README.md` 파일을 이 압축 파일의 버전으로 덮어써 주세요. `package.json`도 함께 올려도 됩니다. **`index.html`만 교체하면 동작하지 않습니다.**
2. GitHub `Commit changes` 후 Render 자동 배포가 활성화되어 있으면 서버가 다시 배포됩니다. Render에서 최신 커밋이 `Live`인지 확인해 주세요.
3. 초기 배포: Node.js 18+, Render **Web Service**, 빌드 `npm install`, 시작 `npm start`, Root Directory 공란. 로컬에서는 `npm install`, `npm start`, http://localhost:3000 접속.
4. **배포 시 이전 버전 브라우저 탭은 모두 새로고침**해야 합니다. 기존 V4 클라이언트의 `cut` 메시지는 V5 서버에서 의도적으로 거절합니다(참치 수량 중복 증가 방지).

## 게임 플레이

- 방 코드: 1~64자 한글·숫자·영문·기호 자유 입력. 없으면 자동 생성. 방당 최대 **8명**, 방별 독립 상태.
- `셰프 맡기`: 방에서 **1명만** 사용. 셰프는 썰기/연속 썰기/새 참치 준비 가능.
- **조리 관람:** 셰프와 손님 모두 기본 `관람 · 가게 전경` 시점으로 진입합니다. 썰기 버튼은 이 상태에서도 사용할 수 있고, 더 가까이 보려면 `비스듬히`로 전환하면 됩니다. 셰프의 칼질이 서버에서 승인되는 즉시 **같은 방 전체에 3D 칼 애니메이션과 절단 조각이 나타납니다.** 카메라 버튼으로 다른 각도도 자유롭게 볼 수 있습니다.
- **중간 입장:** 그 참치를 이미 썰어 둔 조각 기록과 진행 중인 칼질 상태를 서버에서 받아 장면을 복구합니다.
- **각자 테이블:** 손님 아바타 앞에 개인 작은 테이블과 접시가 있습니다. 셰프의 `손님 접시에 내놓기`를 누르면 썰어 둔 조각이 현재 방의 사람들에게 나뉘어 개인 접시에 놓입니다. 조각 수보다 사람이 많으면 일부는 아직 못 받을 수 있으므로 더 썰어 내 주세요.
- `회 먹기`: **내 접시**의 회로 별도 식사 화면 진입. 남의 젓가락이나 남의 회 수량을 건드리지 않습니다. 간장·와사비·젓가락·사케는 나만 조작합니다.
- 셰프 혼자 접속했어도 썰어 둔 회를 자동으로 자기 접시에 내놓고 먹을 수 있습니다. 별도 `혼자 썰어 먹기` 버튼은 없습니다.
- `새 참치 준비`: 썰어 둔 것은 개인 접시에 자동으로 나누어 주고 새 참치 블록을 만듭니다. **각자 접시에 놓인 회는 지워지지 않습니다.**
- `자리 넘기기`: 남은 썬 회를 개인 접시에 내놓고 셰프 역할을 해제합니다. 칼질 도중에는 완료 후 시도해 주세요.
- 누군가 퇴장할 때 남은 개인 접시 회는 서버의 예비분으로 반환됩니다. 예비 회가 있으면 다른 사람에게 `내 접시에 더 담기` 버튼이 보입니다.
- 채팅·닉네임·아바타 옷 색상 유지.

## 구현 원리 및 주의

- **서버 권위형:** 클라이언트가 단순히 `몇 점을 썰었다`고 통보하는 기존 구조 대신 서버가 `slice` 요청을 검증하고, 두께·속도·시작시각·식별자를 가진 `cut-animation`을 방에 방송합니다. 잘린 조각 수는 서버의 타이머가 확정하므로 중복 수량 증가를 막습니다.
- **개별 수량:** `users[].plate`가 사용자의 독립 참치 수량이고 서버는 사용자의 접시에서만 `eat`를 차감합니다. 다른 사람의 회를 동시에 가져갈 수 없습니다.
- **시각 효과 범위:** 실제 셰프/손님 팔·젓가락의 움직임까지 다른 사람 화면에 재현하는 기능은 아닙니다. 셰프의 **칼 애니메이션과 참치 절단 결과**, 손님 아바타, 각자 테이블·접시·수량을 동기화한 단계입니다. 각자의 간장/와사비/사케 조작은 개인 화면에서 처리합니다.
- 사용자의 게임 화면에는 실시간 조리 관람 시점과 각자 1인칭 식사 시점이 있습니다. **식사 화면에 진입한 사람은 현재 조리 전경이 아니라 자기 테이블을 봅니다.** `← 썰기로`를 누르면 다시 관람 화면으로 돌아올 수 있습니다.
- 서버가 다시 시작하거나 해당 방에서 모두 퇴장하면 방 상태가 사라집니다. Render 무료 서버 절전 및 재배포 시에도 초기화될 수 있습니다.
- Three.js는 원본과 동일하게 외부 CDN을 사용합니다. 최초 로딩 시 인터넷 연결이 필요합니다.

## 검증 상태

- 서버 가상 WebSocket 다중 접속 테스트 통과: 양쪽 칼질 이벤트 전송, 늦은 입장자의 참치 기록 복구, 한 사람 식사 시 타인 접시 수량 불변, 참치 초기화, 셰프 교대, 방 간 격리.
- `server.js`, `multiplayer.js` 및 HTML에 포함된 JS의 **Node.js 문법 검사 통과**.
- 테스트 환경의 Chromium이 로컬 주소 접근을 막아 **실제 3D 화면 렌더링과 Render 실서버에서의 8명 동시 접속은 검증하지 못했습니다**. 최종 3D 배치는 Render에 배포한 뒤 PC 브라우저 두 창(또는 두 기기)으로 확인해 주세요.
