# 작은 스시집 V8 — 맛 중심 칭찬·혹평 확장

기존 V7의 오프라인 모드, 두께 동기화 및 방 코드 자유 입장, 8인 실시간 멀티, 칼질 관람, 손님별 접시, 아바타 채팅, 셰프의 몰래 집어먹기, 회 음미/사케 기능을 유지한 업데이트입니다.

## 1. 오프라인 플레이

### A. 가장 간단한 혼자 플레이 (인터넷으로 접속한 웹에서도 가능)
- Render 사이트에 접속한 뒤 첫 화면의 **`혼자 즐기기 · 서버 없이`** 버튼 클릭.
- Node.js 서버와 WebSocket 세션이 없어도 혼자 썰기 → 접시에 내기 → 간장/와사비 → 먹기 → 새 참치 준비가 동작합니다.
- `index.html`을 PC에서 직접 열어도 자동으로 1인 모드가 켜집니다. 단, `index.html`은 Three.js를 CDN에서 불러오므로 **인터넷 접속이 필요합니다.** 이는 멀티플레이 서버 접속과는 별개입니다.

### B. 인터넷까지 완전히 끊긴 상태에서 오프라인 사용 (Windows)
1. ZIP을 풀고, **인터넷 연결이 있을 때 단 한 번** `setup-offline.bat`를 실행합니다. 윈도우 PowerShell이 3D 엔진 `three.min.js`와 `OrbitControls.js`를 `vendor/`로 받습니다.
2. 이후 `offline.html`을 더블클릭하면 **인터넷도 서버도 없이** 혼자 즐길 수 있습니다. `offline.html`, `multiplayer.js`, `vendor/` 폴더를 함께 보관하세요.
3. 3D 엔진은 Three.js r128 버전을 고정합니다. 외부 CDN을 쓰는 `index.html`과 달리 `offline.html`은 로컬 `vendor/` 파일만 사용합니다.

**주의:** 제작 환경에서 외부 3D 엔진 파일을 직접 내려받을 수 없어 ZIP에는 해당 파일이 들어 있지 않습니다. 완전한 무인터넷 실행은 위 1회 다운로드가 필요합니다. Windows가 아닌 시스템에서는 아래 두 링크를 `vendor/`에 직접 저장하면 됩니다:
- https://cdn.jsdelivr.net/npm/three@0.128.0/build/three.min.js
- https://cdn.jsdelivr.net/npm/three@0.128.0/examples/js/controls/OrbitControls.js

오프라인 진행 상태는 브라우저를 종료하면 초기화됩니다. 오프라인 모드에는 다른 실제 플레이어가 없습니다.

## 2. 두께별 동기화
- 서버가 절단 시 실제 적용한 두께 **0.12~0.45**를 방 참가자 전원에게 전송합니다.
- 절단 애니메이션/조각 두께뿐 아니라, **접시에 배분되는 개별 참치 조각에도 두께 배열(`plateCuts`)**을 보존합니다.
- 조각 크기는 손님 테이블과 1인칭 식사 접시에 반영됩니다.
- 각 조각은 한 명의 접시에만 배분됩니다. 먹거나 훔치면 그 사람 접시에서 실제 한 조각만 사라집니다.
- 잘린 횟수와 접시 개수는 1:1로 정확히 대응하며, 컷별 두께 정보도 보존됩니다.

## 3. 손님들의 맛 칭찬 / 맛 혹평 (V8)
- 버튼 이름을 **👏 맛 칭찬 / 😖 맛 혹평**으로 변경했습니다. 기존 서버 메시지 `react`의 `kind: praise|boo`는 이전 클라이언트와의 호환을 위해 그대로 유지합니다.
- 칭찬은 기존 6개에서 **일반 칭찬 50개 + 얇은 회 전용 8개 + 두꺼운 회 전용 8개**로 확장했습니다.
- 혹평은 셰프의 태도나 회 도난을 놀리는 내용 대신 **맛, 지방, 비린 향, 식감, 뒷맛**을 평가하는 **일반 혹평 38개 + 얇은 회 전용 6개 + 두꺼운 회 전용 6개**로 변경했습니다.
- 해당 손님이 마지막으로 먹은 회의 두께가 0.19 이하 또는 0.31 이상이면, 그 두께와 어울리는 전용 대사도 후보에 포함됩니다. 아직 먹지 않았다면 일반 맛 평가만 선택됩니다.
- 연속으로 같은 문장이 선택되지 않도록 방지했습니다. 메시지는 기존처럼 **발신자의 3D 아바타 말풍선과 방 채팅**에 동시에 표시됩니다.
- 한 손님의 반응 연타 제한 2.3초, 셰프 본인 평가 제한, 방별 횟수 집계는 기존과 동일합니다.
- 모든 대사는 가상의 과장된 요리만화풍 시식평이며, 실제로 계산되는 맛 품질 점수가 아닙니다.

## GitHub & Render 배포
기존 `sushi-bar` 리포지토리 최상위에 `index.html`, `server.js`, `multiplayer.js`, `package.json`, `README.md`를 교체합니다. `offline.html`, `vendor/`, `setup-offline.*`는 PC 오프라인 배포용이며, GitHub 업로드는 선택 사항입니다. Render에서 기존 `npm install` 및 `npm start` 그대로 사용합니다.

## 개발자 검증
`node --check server.js`, `node --check multiplayer.js`, 인라인 HTML JS 구문 검사. 서버 가상 소켓 테스트에서 두께별 절단·배분·식사·몰래 먹기·반응 이벤트를 검증했고, 브라우저 DOM 기반 오프라인 상태 엔진은 V7에서 테스트된 내용을 유지하며, V8은 시식평 선택 로직을 별도로 검사했습니다. 실제 Render 배포 및 외부 Three.js 내려받기는 사용자의 환경에서 확인해야 합니다.
